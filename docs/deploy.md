# دليل النشر — رفيق الداعية

هذا الدليل لمن ينشر أول مرة. اتبع الخطوات بالترتيب:
**GitHub ← Render (الـ Backend) ← Vercel (الواجهة) ← الربط ← الاختبار**.

> **لا تكتب أي مفتاح أو كلمة مرور في ملف داخل المستودع.** القيم السرية مكانها لوحة Render فقط، و`backend/.env` على جهازك فقط.

---

## 0) قبل البدء

1. **قاعدة البيانات جاهزة:** الجداول ودالة البحث الهجين موجودة في Supabase، ومستخدم المدير موجود. لا تحتاج لتشغيل `schema.sql` أو `init_db.py` مرة أخرى.
2. **ارفع المشروع إلى GitHub** (مستودع خاص Private أفضل):
   ```powershell
   cd D:\Da-iah-Copilot
   git remote add origin https://github.com/<اسمك>/<اسم-المستودع>.git
   git push -u origin main
   ```
   قبل الرفع تأكد أن `git status` لا يُظهر `backend/.env` ولا `frontend/.env.local`. الملفان مستثنيان في `.gitignore`.
3. **جهّز هذه القيم في مكان آمن** (مثل مدير كلمات المرور). ستلصقها في Render:

| المتغير | من أين تحصل على قيمته |
|---|---|
| `SUPABASE_URL` | Supabase ← مشروعك ← **Project Settings ← Data API ← Project URL** (شكله `https://xxxx.supabase.co`) |
| `SUPABASE_SERVICE_KEY` | Supabase ← **Project Settings ← API Keys ← Secret keys** (يبدأ بـ `sb_secret_`)، أو مفتاح `service_role` في تبويب Legacy. **سري جداً**: يتجاوز كل الحماية |
| `GEMINI_API_KEY` | [Google AI Studio](https://aistudio.google.com/apikey) ← **Create API key** |
| `JWT_SECRET` | أنشئ قيمة عشوائية جديدة للإنتاج (32 حرفاً على الأقل): `cd backend ; .venv\Scripts\python.exe -c "import secrets; print(secrets.token_urlsafe(48))"` |
| `CORS_ORIGINS` | رابط موقعك على Vercel (ستعرفه في الخطوة 2). اكتبه بلا `/` في النهاية |

> `ADMIN_EMAIL` و`ADMIN_PASSWORD` **لا تُضاف إلى Render**. الخادم لا يستخدمهما؛ هما فقط لـ `init_db.py` والاختبارات على جهازك. الدخول للوحة يكون بالحساب الموجود في قاعدة البيانات.

## 1) Render — الـ Backend

### الطريقة أ: Blueprint (الأسهل، تقرأ `render.yaml`)
1. ادخل [dashboard.render.com](https://dashboard.render.com) وسجّل بحساب GitHub.
2. اضغط **New ← Blueprint**.
3. اختر مستودع المشروع. إن لم يظهر، اضغط **Configure account** واسمح لـ Render بالوصول إليه.
4. سيقرأ Render ملف `render.yaml` ويعرض خدمة واحدة: `daiah-backend` (Python، الخطة Free).
5. سيطلب قيم المتغيرات السرية. الصق القيم من الجدول أعلاه:
   - `SUPABASE_URL` و`SUPABASE_SERVICE_KEY` و`GEMINI_API_KEY` و`JWT_SECRET`.
   - `CORS_ORIGINS`: إن لم تعرف رابط Vercel بعد، اكتب مؤقتاً `https://placeholder.invalid`، وستغيّره في الخطوة 3.
6. اضغط **Apply**. البناء الأول يأخذ 2–5 دقائق، وتتابعه في تبويب **Logs**.

### الطريقة ب: Web Service يدوياً
**New ← Web Service ←** اختر المستودع، ثم املأ:

| الحقل | القيمة |
|---|---|
| Name | `daiah-backend` |
| Language | Python 3 |
| Branch | `main` |
| Root Directory | `backend` |
| Build Command | `pip install -r requirements.txt` |
| Start Command | `uvicorn app.main:app --host 0.0.0.0 --port $PORT` |
| Instance Type | Free |

ثم:
- في **Environment Variables** أضف المتغيرات الخمسة من الجدول، ومعها `PYTHON_VERSION` = `3.13`.
- في **Advanced ← Health Check Path** اكتب `/api/health`.
- اضغط **Create Web Service**.

### التحقق
1. انسخ رابط الخدمة من أعلى الصفحة، مثل `https://daiah-backend.onrender.com`. قد يضيف Render حروفاً للاسم إن كان مستخدماً، فاعتمد الرابط الظاهر.
2. افتح `https://<رابطك>.onrender.com/api/health` في المتصفح. يجب أن تظهر:
   ```json
   {"status":"ok"}
   ```
3. صفحة `/docs` **مغلقة في الإنتاج عمداً** (تظهر 404). هذا طبيعي.

> **إن فشل البناء أو التشغيل:** راجع تبويب **Logs**. أكثر الأسباب شيوعاً: متغير ناقص أو منسوخ بمسافة زائدة.

## 2) Vercel — الواجهة

1. ادخل [vercel.com](https://vercel.com) بحساب GitHub، ثم **Add New… ← Project**.
2. اختر المستودع ← **Import**.
3. في صفحة الإعداد:
   - **Project Name:** اسم قصير، مثل `daiah`. رابط موقعك سيكون `https://daiah.vercel.app`. إن كان الاسم مأخوذاً سيظهر لك اسم آخر، فاعتمد ما يظهر.
   - **Root Directory:** اضغط **Edit** واختر **`frontend`**. هذه أهم خطوة.
   - **Framework Preset:** يُكتشف تلقائياً (Next.js). لا تغيّر أوامر البناء.
4. افتح **Environment Variables** وأضف متغيرين فقط:

| المتغير | القيمة |
|---|---|
| `NEXT_PUBLIC_API_URL` | رابط Render من الخطوة 1، مثل `https://daiah-backend.onrender.com` (بلا `/` في النهاية) |
| `NEXT_PUBLIC_SITE_URL` | رابط موقعك على Vercel، مثل `https://daiah.vercel.app` |

5. اضغط **Deploy**. بعد 1–3 دقائق اضغط **Visit**.

> **حماية مدمجة:** إن نسيت أحد المتغيرين، أو كتبت `localhost`، أو رابطاً بلا `https`، يفشل البناء برسالة عربية واضحة. أضف المتغير من **Settings ← Environment Variables** ثم **Deployments ← ⋯ ← Redeploy**.
>
> لا تضع أي مفتاح سري في Vercel: كل ما يبدأ بـ `NEXT_PUBLIC_` يظهر للزوار.

**إصدار Node:** المشروع يعمل على Node 20.19+ أو 22 أو 24. إعداد Vercel الافتراضي مناسب.

## 3) الربط بين الجهتين (CORS)

الـ Backend لا يقبل طلبات إلا من الروابط المكتوبة في `CORS_ORIGINS`. هذا ما يمنع أي موقع آخر من استخدام الـ API من متصفح الزائر.

1. في Render افتح الخدمة ← **Environment**.
2. عدّل `CORS_ORIGINS` إلى رابط Vercel بالضبط، مثل `https://daiah.vercel.app`.
   - بلا `/` في النهاية، وبـ `https`.
   - لأكثر من رابط (مثل نطاق خاص لاحقاً) افصل بفاصلة: `https://daiah.vercel.app,https://www.example.org`.
   - لا تستخدم `*`، فالخادم يتجاهلها.
3. اضغط **Save, rebuild, and deploy**، أو **Save** ثم **Manual Deploy ← Deploy latest commit**.
4. انتظر حتى تصير الحالة **Live**.

> روابط المعاينة في Vercel (مثل `daiah-git-xyz.vercel.app`) غير مسموحة إلا إذا أضفتها. هذا مقصود.

## 4) اختبار ما بعد النشر (قائمة تحقق)

نفّذها بالترتيب، وضع ✓ لكل بند:

- [ ] `https://<render>/api/health` ← `{"status":"ok"}`
- [ ] الصفحة الرئيسية تفتح. القاعدة فارغة الآن، فتظهر رسائل واضحة مثل «لم تُضف أقسام بعد» و«لا توجد مواد منشورة بعد».
- [ ] بدّل اللغة إلى English من الأعلى، ثم ارجع للعربية.
- [ ] `/admin/login` ← ادخل ببريد المدير وكلمة مروره. يجب أن تفتح الرئيسية، وفي «حالة النظام» تظهر قاعدة البيانات وGemini بحالة سليمة.
  إن ظهرت رسالة اتصال أو CORS، راجع الخطوة 3.
- [ ] **الأقسام** ← أنشئ قسماً تجريبياً، مثل «اختبار النشر».
- [ ] **المنشورات ← منشور جديد** ← عنوان ونص قصير ← احفظ ← **نشر**. يجب أن تظهر رسالة النشر بلا تحذير فهرسة.
- [ ] افتح `/library` في الموقع، ثم صفحة المادة: يظهر النص كاملاً.
- [ ] `/assistant` ← اسأل سؤالاً بصياغة قريبة من نص المادة ← يجب أن يظهر «نص معتمد من المنصة» بنصها حرفياً.
- [ ] اسأل سؤالاً بعيداً، مثل «ما عاصمة أستراليا؟» ← تظهر رسالة «غير متوفرة».
- [ ] **التنظيف:** احذف المنشور التجريبي ثم القسم. أسئلتك التجريبية تبقى في سجل الأسئلة؛ في «الأسئلة غير المجابة» اضغط **تجاهل** على السؤال البعيد.

## 5) نوم Render المجاني

- الخطة المجانية **توقف الخدمة بعد 15 دقيقة بلا طلبات**. أول طلب بعدها يوقظها في **30–60 ثانية تقريباً**، ويبدو الموقع بطيئاً أو تظهر رسالة «تعذّر الاتصال».
- **قبل العرض أو التحكيم بدقيقتين:** افتح `https://<render>/api/health` وانتظر `{"status":"ok"}`، ثم افتح الموقع.
- الكاش في ذاكرة الخادم يُمسح عند النوم، فأول سؤال بعد الاستيقاظ أبطأ قليلاً. هذا طبيعي.

### إبقاؤه مستيقظاً بـ UptimeRobot (مجاني)
1. سجّل في [uptimerobot.com](https://uptimerobot.com).
2. **+ New monitor**:
   - Monitor Type: **HTTP(s)**
   - URL: `https://<render>/api/health`
   - Monitoring Interval: **5 minutes**
3. **Create Monitor**. سيطلب الرابط كل 5 دقائق، فلا تنام الخدمة، ويرسل لك بريداً إن توقفت.

> الخطة المجانية في Render تعطي 750 ساعة شهرياً، وهي تكفي خدمة واحدة تعمل طوال الشهر. لا تشغّل خدمات مجانية أخرى على نفس الحساب مع UptimeRobot حتى لا تنفد الساعات.

## 6) بعد النشر بدون Claude Code

> **تنبيه مهم:** موقع الإنتاج وجهازك يستخدمان **نفس قاعدة Supabase**. أي تعديل من اللوحة المحلية يظهر في الموقع المنشور.
> ملفات الاختبار (`*_test.py`) تنشئ بيانات مؤقتة وتحذفها، لكنها تضيف لحظياً مواد تجريبية للموقع الحي. لا تشغّلها وقت العرض.

### أ) استيراد المحتوى من CSV
1. **أنشئ الأقسام أولاً:** **الأقسام ← قسم جديد** لكل قسم، واختر مساره (منهجية الدعوة، الشبهات، التعريف بالإسلام، المسلم الجديد). انسخ **الرابط المختصر (slug)** لكل قسم.
2. **المنشورات ← استيراد** ← **قالب CSV فارغ**. افتحه في Excel أو Google Sheets.
3. **الأعمدة الإلزامية:**
   - `category`: واحد من `methodology` و`shubuhat` و`intro_islam` و`new_muslim`.
   - `title_ar` و`content_ar`.
4. **أعمدة مفيدة:**
   - `section_slug`: من الخطوة 1. بدونه توضع المادة في أول قسم في المسار.
   - `content_en` و`title_en` للنسخة الإنجليزية.
   - `tags` مفصولة بـ `|`.
   - `external_ref`: رابط المصدر، يبدأ بـ `http`.
   - `source_name` و`summary_ar`.
   - `content_type`: واحد من `article` و`booklet` و`leaflet` و`shubha_response`.
5. **احفظ الملف** بصيغة **CSV UTF-8** (في Excel: حفظ باسم ← *CSV UTF-8 (Comma delimited)*). الحد 500 صف و5 ميغابايت للملف الواحد.
6. **ارفع الملف** في صفحة الاستيراد، واختر الحالة بعد الاستيراد («مسودة» أو «قيد المراجعة») ← **معاينة**.
7. **راجع الأخطاء** بالأحمر في كل صف. الصفوف التي فيها أخطاء لا تُستورد. صحّحها في الملف وأعد المعاينة، أو استورد الصالح فقط.
8. اضغط **استيراد** ← **تأكيد الاستيراد**.
9. **المواد لا تُنشر تلقائياً.** افتح **المراجعة**، وراجع كل مادة، ثم انشرها. النشر هو ما يضيفها للبحث والمساعد.

النص يُحفظ حرفياً كما في الملف. مثال معبأ بصف واحد في `docs/content-template.csv`.

### ب) إضافة المراكز المعتمدة
**الإدارة ← المراكز المعتمدة ← إضافة المركز** ← الاسم (إلزامي)، والدولة، والرابط (`https://…`)، والتواصل (بريد أو هاتف) ← حفظ.
تظهر المراكز في رد المساعد عندما لا توجد إجابة، وفي صفحة «المسلم الجديد».

### ج) ضبط العتبة واختبارها
**العتبة (حد الارتباط)** هي أقل تشابه يجعل المساعد يعرض مادة. تحتها يعرض «غير متوفرة» مع أقرب مادة والمراكز.
- **عالية جداً:** يقول «غير متوفرة» لأسئلة لها إجابة.
- **منخفضة جداً:** يعرض مادة غير مناسبة للسؤال.
- **الحالية:** 0.59، ومعايرتها كانت على بيانات تجريبية. **أعد معايرتها بعد نشر المحتوى الحقيقي** (20 مادة على الأقل).

**الطريقة:**
1. افتح **الذكاء الاصطناعي ← مختبر الاختبار**. أسئلة المختبر لا تُسجَّل في سجل الأسئلة.
2. **أسئلة مطابقة (10 على الأقل):** أسئلة **منشورة** إجاباتها في المنصة، لكن بصياغة الناس لا بنص العنوان. نوّع بين العامية، والأخطاء الإملائية، والإنجليزية.
   سجّل لكل سؤال **درجة تشابه المادة الصحيحة** من قسم «ما استرجعه النظام».
3. **أسئلة بعيدة (10 على الأقل):** أسئلة **لا** توجد إجابتها في المنصة، ومنها أسئلة قريبة من المجال لكنها غير مغطاة.
   سجّل **أعلى درجة** ظهرت لكل سؤال.
4. **اختر القيمة:**
   - لتكن **أ** = أقل درجة صحيحة في الخطوة 2، و**ب** = أعلى درجة بعيدة في الخطوة 3.
   - إن كانت أ أكبر من ب: اختر قيمة بينهما، أقرب قليلاً إلى **أ**. مثلاً أ = 0.66 و ب = 0.56 ← اختر 0.62.
   - إن تداخلت الدرجات: فضّل الأمان وارفع العتبة. قول «غير متوفرة» مع إحالة لمركز أفضل من عرض مادة لا تجيب السؤال. وأضف مواد تغطي الأسئلة الضعيفة.
5. **احفظ القيمة:** **الذكاء الاصطناعي ← الإعدادات والتعليمات** ← حرّك **حد الارتباط (العتبة)** (المدى 0.50–0.95) ← **حفظ**. كل حفظ يُحفظ معه إصدار سابق، وتستطيع **استرجاعه** من قائمة الإصدارات.
6. **أعد أسئلة المختبر:** يظهر «فوق العتبة / تحت العتبة» لكل نتيجة. المساعد في الموقع يأخذ القيمة الجديدة خلال 15 ثانية.
7. **بعد أسبوع:** راجع **الأسئلة غير المجابة**. إن وجدت أسئلة لها مادة منشورة بدرجة قريبة من العتبة، فخفّضها قليلاً أو حسّن عنوان المادة.

### د) تغيير كلمة مرور المدير
1. في اللوحة: القائمة ← **حسابي** ← قسم كلمة المرور.
2. أدخل **كلمة المرور الحالية**، ثم **الجديدة** (8 أحرف على الأقل) و**تأكيدها** ← **حفظ**.
3. التغيير يكون في قاعدة البيانات مباشرة، فيسري على الموقع المنشور وعلى جهازك معاً.
4. **على جهازك:** حدّث `ADMIN_PASSWORD` في `backend/.env` إلى الكلمة الجديدة، حتى تعمل الاختبارات. لا حاجة لتعديل شيء في Render.

## 7) ملخص الحماية المفعّلة في الإنتاج
- **CORS:** لا يُسمح إلا بالروابط في `CORS_ORIGINS`. فراغها في الإنتاج يعني رفض كل المتصفحات، مع تحذير في سجل Render.
- **الإنتاج يُكتشف تلقائياً:** على Render (`RENDER=true`) تُغلق `/docs` و`/openapi.json`، ويُرفض `JWT_SECRET` أقصر من 32 حرفاً.
- **حد الطلبات على `/api/chat`:** 20 طلباً في الدقيقة لكل IP.
- **حد الدخول:** 10 محاولات فاشلة كل 15 دقيقة لكل IP.
- **رسائل الخطأ:** عامة بالعربية، والتفاصيل في سجل الخادم فقط، والقيم السرية تُحذف منها.
- **نص المواد:** يُنظَّف بـ DOMPurify في الخادم والمتصفح قبل عرضه.
- **الواجهة بلا أسرار:** فيها رابطان عامان فقط.
